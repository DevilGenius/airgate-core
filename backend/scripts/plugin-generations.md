# 插件进程更新

开发与正式安装共用 `updatePlugin → preparePlugin → publishPlugin → retireGeneration`。开发环境先构建可执行文件，正式环境校验下载内容；后续步骤完全相同。

## 请求和进程

1. 新文件进入独立版本目录，初始化、配置读取、健康检查、模型/路由读取和资源提取均在候选阶段完成。
2. 候选上线后，新调用原子地取得当前实例并登记引用；转发、流式响应、账号刷新、管理代理和任务执行均保留引用到调用结束。
3. 旧进程进入 SDK Drain 阶段，停止新的后台任务准入，并等待已有调用自然结束。最长等待 **30 分钟**；到期后停止并回收旧进程，即使仍有长请求。
4. 每个插件最多一个活动进程和一个退出中的进程。后者未退出时拒绝下一次更新，防止连续更新积累进程。全局同时准备上限为 8。
5. 候选阶段失败时保留活动实例。Core 停机取消候选准备，并在既有停机预算内回收进程。

构建预算三分钟，候选准备预算三十秒。插件 Stop RPC 受十秒上限与剩余总预算共同限制。30 分钟排空期限到达后不会再额外等待十秒；Core 自身关闭仍使用原有总停机预算。

## SDK 标准边界

SDK 定义版本化 Runtime v1 协议，通过现有 gRPC 通道传输；Core 不直接调用某个 provider 的私有生命周期 API。

- `RuntimeProvider` 声明资源，`RuntimeDrainer` 停止插件后台准入。
- `RuntimeSettingsHandler` 接收通用系统配置；插件自行解释支持的配置键。
- `RuntimeCallbackHandler` 接收通用 HTTP 回调。Core 只绑定受限的回环地址、转交请求和管理引用，不识别 OAuth 参数、状态键或平台名称。
- `RuntimeState` 定义读取、比较更新与一次性消费接口。Host 客户端是 SDK 提供的实现，gateway 不依赖 Core 的存储结构。

回调资源按插件身份、名称和监听地址声明，新旧代共享物理监听；候选失败只释放自己的引用，最后一个引用结束后才关闭资源。缺少 Runtime v1 的旧 SDK 插件不进入候选上线流程。

## 文件与开发构建

- `<plugins>/.generations/<uuid>/plugin[.exe]`：不可变二进制。
- 同一目录的 `assets/`：二进制内嵌的前端文件。
- `<plugins>/<plugin-id>/active.json`：当前版本、校验和、上一版本和安装来源。

文件同步后才替换清单；Windows 使用 MoveFileEx，Linux 同步目录。恢复清理先收集所有清单及活动/退出中进程的引用，仅移除未引用的版本。清单损坏或无法读取时停止清理。文件准备和清理互斥，请求处理不持有该文件锁。

所有六个插件均删除了按工作目录查找前端文件的回退逻辑。开发脚本把 Vite watch 产物写入插件的 Go embed 目录；源码或嵌入资源变化触发同一套更新流程。指纹包含文件名、大小和修改时间，能够发现删除；构建期间发生变化的候选不会上线。

旧的平铺二进制、独立开发重载与直接读取 web/dist 的运行路径已移除。首次部署此 Core 版本时，需要通过插件安装/更新生成新格式安装；不自动加载旧平铺安装。

## 需要跨进程的状态

Core 提供按插件身份隔离的 `runtime.state`，支持读取、批量读取、版本比较更新及一次性消费。共享状态以 Core 为生命周期，默认一小时过期，总计最多 65,536 项、128 MiB，单项最多 256 KiB。

- OpenAI：对话继续状态、Anthropic 会话指纹和 OAuth PKCE 状态。
- Claude：稳定会话标识和 OAuth PKCE 状态。
- Kiro：OAuth/设备授权状态、回调结果；插件通过 SDK 声明 3128 回调监听，OAuth 解析和验证仍在 Kiro 内执行。

可用的 OpenAI 私有数据库快照按键恢复，并以“仅缺失时写入”的方式填充共享状态，避免覆盖旧进程的晚到更新。未授予角色创建权限时保持空 plugin_dsn，不替换成 Core DSN、不增加数据库权限。没有新增数据库表、字段或回填任务。

迁移的是需要跨进程延续的短期状态，并不是把 gateway 的所有参数和逻辑移入 Core。协议转换、鉴权规则、状态内容和回调业务都由插件拥有。共享状态用于同一个 Core 下的新旧进程交接，不构成多个 Core 实例之间的全局版本保证。Core 自身重启会结束内存状态；快照恢复取决于是否配置了可用的私有存储。自动 OAuth 回调监听不可用时，Kiro 仍支持手动粘贴回调。

## 验证与发布

真实子进程测试覆盖：旧流保持连接、新调用进入新进程、晚到状态跨进程可见、候选失败保留旧版本、第三个进程被拒绝、停机取消候选、重启恢复和清理保留引用。30 分钟策略以短时钟测试验证实际子进程到期退出；通用回调测试验证监听复用和失败候选的引用释放。共享状态竞争测试重复 20 次；各 gateway 状态测试重复 5 次。

本地通过 `AIRGATE_GENERATION_CONFIG=<本地配置>` 显式启用 `TestLocalGatewayGenerationReload`；它逐个重载三个 gateway，不发送上游模型请求。SDK 标准化后的最终实测为 1.056 / 1.105 / 0.935 秒，154 次健康探针全部 HTTP 200，插件 index.js 均 HTTP 200。Core 进程保持运行，回调监听由统一资源管理器持有。

已验证八个仓库的 Go 测试、前端受影响的 9 项测试、项目完整构建/静态检查，以及 Core 与三个 gateway 的 Linux amd64 构建。原有使用统计后台维护流程未改动。

本地完整清理移除了六个旧 assets 目录，保留每个插件当前与上一版本，共 12 个版本目录。前端资源仅从活动版本读取。

发布必须先发布 SDK，再更新 Core 与所有插件的 SDK 依赖并构建。当前开发工作区使用本地 SDK；本次未推送或发布版本。
